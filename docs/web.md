# Web 界面

`web/` 提供单用户日常资料管理界面：图片/图文/文本导入、处理状态查看、三类检索、原件与解析字段展示、编辑、失败重试和删除。首版覆盖 W0–W2（骨架与契约、浏览与导入、检索与详情）与 T05 连接状态页；缩略图依赖 T06，未接入时保持“待接入”，不虚构状态。

连接状态页只读 `GET /api/health`，逐项展示 API、数据库、Embedding、当前存储 profile、可选视觉、可选决策与 Worker 的检查结果、检查范围和建议动作；Worker 尚无心跳，固定显示“未监测”，接口与页面都不推断队列状态。契约与错误码见 [连接状态 API](health.md)。

前端只调用同源 `/api` 接口，不连接 PostgreSQL、RustFS/S3 或模型服务，不在浏览器保存服务端凭证；用户文字、Caption、OCR 一律按纯文本渲染，不解释为 HTML。

## 页面与后端能力

| 路由 | 作用 | 使用的接口 |
| --- | --- | --- |
| `#/library` | 浏览分页 + 三类检索、标签 AND、Top-K、状态/输入类型筛选 | `GET /api/resources`、`POST /api/search` |
| `#/import` | 单份导入、批量多选及目录上传、预览、清单恢复与状态轮询 | `POST /api/resources`、`GET /api/resources/{id}`、`GET /api/imports/options`、`POST /api/imports/resolve` |
| `#/resources/<id>` | 原件与内容两栏、警告与错误、编辑、失败重试、删除 | `GET`、`PATCH`、`POST /retry`、`DELETE`、`GET /original` |
| `#/connections` | 只读展示七项依赖的检查结果、检查范围与建议动作，进入时检查一次、可手动重跑 | `GET /api/health` |

采用哈希路由，静态服务器无需 SPA 回源规则；刷新、前进后退均可用。页面或资源 ID 改变时回到页首并聚焦主内容，前进后退也采用该规则；同页轮询与编辑不抢焦点。跳到主要内容不会改变 hash。

浏览与搜索严格分开：状态与输入类型筛选只出现在 `GET /api/resources`，不会传给 `POST /api/search`；搜索接口无 `total` 与分页，卡片显示 cosine 得分（不是概率、允许为负）与 `mode=vector`，字段少于详情，因此不显示状态或 revision。清空查询即回到浏览模式。多个标签以重复 `tags` 参数提交，按 AND 匹配；无标签目录接口，标签为手工输入。

## 状态与轮询

- 详情页与导入结果页按资源 ID 轮询服务端状态：页面可见时约 2 秒一次，`ready`/`failed` 停止；标签页隐藏即暂停，恢复可见时立即读取；失败退避至最多 30 秒，同时保留最后一次成功数据并标注“可能不是最新”。
- 超过观察窗口（默认 120 秒）仍为处理中时，提示“仍在处理，可稍后查看”，不改写服务端状态，也不提供 Worker 恢复按钮。
- 浏览列表在存在 `pending/processing` 且页面可见时按 5 秒刷新当前页，整页共用一个定时器，卡片不各自轮询。
- 搜索不会自动重跑（避免重复消耗模型）；返回资料库时展示同一标签页内的上次结果并提供“重新搜索”。编辑或删除某份资料后，其缓存命中立即移除，浏览列表强制刷新。
- 隐藏页面、切换资料和卸载会取消旧详情请求；额外的请求标识会隔离忽略取消的晚到响应。缓存拒绝低 revision、同版本的旧时间戳和终态回退。编辑/重试成功会重新启动对应版本的轮询。

图片选择区使用原生按钮，隐藏 file input 不嵌套在按钮内部；支持键盘选择、拖放及聚焦后粘贴，窄屏允许提示换行。文件格式和大小的最终校验仍由后端负责。

批量入口默认不递归、跳过相同内容、两个并发上传；支持预览、暂停、仅重试失败项和结果导出。刷新后从 IndexedDB 恢复清单，重选文件并核验 SHA-256 后续传。批量状态每轮按最多 100 个提交标识查询，模型处理按资源 ID 去重统计；详见 [目录与批量导入](imports.md)。

## 编辑规则

编辑只提交变更字段与进入编辑时的 `revision`；没有改动不发送 `PATCH`（后端任何有效编辑都会增加 revision、删除旧索引并重新排队）。Caption/OCR 与配文提供三种明确动作，序列化结果互不相同：

| 意图 | 请求 | 效果 |
| --- | --- | --- |
| 不修改 | 省略字段 | 保留现值 |
| 人工修正或人工置空 | 字符串（含 `""`） | Worker 保留非 null 值 |
| 清空并重新生成 | 显式 `null` | 仅当前路线需要时自动生成；`text_image` 不自动分析 |

仅图片资料可把路线改为 `workflow: null`（重新自动分类）或指定 `structured_image/info_rich_image/visual_image/visdoc`；有配文或纯文本资料不能指定图片路线。首阶段只有结构图片和信息密集图片自动生成 Caption，VisDoc 和视觉图片仅整图编码；OCR 清空后不自动生成。提交前的“将提交的改动”清单列出实际字段。完整规则见 [图片路由](routing.md)。

- 编辑期间的远端轮询不覆盖草稿与编辑基准；远端 revision 变化时提示，可显式“以最新详情为基准比较草稿”或放弃草稿。
- `409` 后只重新读取最新详情，不自动以新 revision 重发旧草稿。
- 重试按钮只对 `failed` 显示，并携带最新 revision；`pending/processing/ready` 不提供该动作。
- 删除前显示资源标题与“UI 内不可恢复”的说明；`204` 无正文可解析，随后移出列表与查询缓存并返回资料库。“已删除”不表示对象已物理清理，清理失败由后端维护命令重试。

## 错误处理

统一读取 `{code,message,details?}`，界面给出简短中文说明并保留 `code` 便于定位；反向代理返回 HTML 时按 HTTP 状态给出含义。`409` 为版本冲突或非法状态，`404` 为资料或原件不存在，`413/415/422` 为输入问题，`502/503/504` 为依赖故障并提示手动重试。`GET` 提供显式重试；`POST/PATCH/DELETE` 不自动重放——上传网络中断时提示“创建结果未知，请先到资料库核查”，避免重复导入。取消查询只结束浏览器等待，不承诺服务端推理被取消。

图片上限（默认 20 MiB）与字段长度（默认 100000 字符）由服务端 `MAX_UPLOAD_BYTES`/`MAX_TEXT_CHARS` 决定，前端只做提前提示，不代替后端判断。

## 开发

```bash
cd web
npm ci
cp .env.example .env.local      # MMKB_API_PROXY_TARGET=http://127.0.0.1:8010
npm run dev                     # http://127.0.0.1:5173，/api 原样代理
```

后端路由自带 `/api` 前缀，代理不重写路径；浏览器与 5173 同源，原件相对地址同样走代理，因此无需为开发放开 CORS。命令、Node 版本与测试清单见 [web/README.md](../web/README.md)。

## 静态部署 {#静态部署}

先构建，再由静态服务器托管 `web/dist`，并在同一入口把 `/api/*` 保留路径转发给 Python API：

```bash
cd web && npm ci && npm run build     # 产物 web/dist
```

要点：

- 上传限额与推理等待超时须不小于后端 `MAX_UPLOAD_BYTES` 与模型超时；代理不得把 `413/5xx` 改写成 SPA HTML 页面。
- 版本化静态资源可长期缓存；`/api` 与原件遵循后端缓存头（原件为 `no-store`）。
- 根页面、静态资源、原件代理和 API 错误都要通过实际入口验证；`npm run preview` 只用于本地查看构建产物，不代理 `/api`。
- 首版不在 FastAPI 内挂载前端静态目录，不新增业务表；若日后改为同进程托管，需补静态兜底不得吞掉 `/api` 404 的测试。
